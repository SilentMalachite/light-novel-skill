# ライトノベル

## 結論

設計ファイルが正本で、本文はその実装である。ログライン、視点、結末、口調を固定してから、頼まれた範囲だけ書く。文体を盛らない。解説・代替案・次巻は頼まれたときだけ出す。

## 前提

- 対象は日本語の商業ラノベおよび Web 小説。純文学ではない。
- 読み手はスマホ縦読みを想定する。速度と章末の未解決が優先。
- 視点は作品で固定する。既定は一人称、または三人称限定。頭跳ねはしない。
- チャットは正本ではない。企画・キャラ・場面カードは markdown に書く。
- 挿絵は本文外。本文だけで場面が立つこと。

## スコープ

依頼を次のどれかに分類し、それ以外はしない。

| 種別 | やること | やらないこと |
| --- | --- | --- |
| 構築 | ログライン、結末、キャラ口調、話ビート、場面カード | 本文、世界設定の百科 |
| 執筆 | 指定シーンまたは指定章の本文 | 前後章の先書き、新キャラの追加 |
| 推敲 | 視点漏れ、説明、AI調、口調の検査と最小修正 | 筋の勝手な改変、文体の盛り直し |

不足があるときの質問は最大3つ。足りないまま本文を書かない。

詳細は必要なときだけ読む。

- 構成と場面カード: [references/structure.md](references/structure.md)
- 文体: [references/style.md](references/style.md)
- 雛形: [references/templates.md](references/templates.md)
- レビュー（Codex 向け）: [references/review.md](references/review.md)

## 仕様

1. 作品の正本は `plot.md`。先頭にログライン1行、視点、一人称、結末、クライマックスを置く。
2. キャラは役割、欠落、行動原理、一人称、語尾、禁止語、口調サンプル3つ。見た目の長文は書かない。口調サンプルが無いキャラのセリフは書かない。
3. 話の比率目安は起10 / 承40 / 転40 / 結10。硬く守らず、結末から逆算する。
4. シーンは場面カードが埋まってから書く。空のシーンは書かない。
5. 本文の既定は Web 体裁。地の文と会話の切り替わりで空行。会話は行頭「」。閉じ括弧前の句点は付けない（「行く」。「行く。」は不可）。！？…は付ける。引用は『』。
6. 紙の体裁を指定されたときだけ、地の文を一字下げ、会話行は下げない。作品内で混ぜない。
7. 章末は未解決を1つ残す。解決して終わる章は禁止。
8. 出力は本文か指定した設計メモだけ。

## 手順

1. 依頼を構築 / 執筆 / 推敲に分ける。
2. `plot.md` を読む。無ければ構築から始める。本文依頼なら先に作って止める。
3. 執筆なら場面カードを埋める。項目は、誰の視点 / 目的 / 入口の圧 / 出口の未解決 / 守る既出事実。
4. 本文を書く。1シーン＝1目的。
5. 書いた直後に、視点の越境、説明台詞、同一語尾3連続、章末フックを検査する。
6. 差分の要約は頼まれたときだけ、3行以内。

Codex でレビューを頼まれたときは本文を書き換えず、[references/review.md](references/review.md) の違反を箇所つきで返す。

## 制約

優先順。

1. 視点を漂わせない。指定視点以外の内心、見えない自分の顔、未知情報を書かない。
2. 設定を講義しない。ルールは選択を縛る場面でのみ出す。説明台詞を書かない。
3. 文学調にしない。比喩は1シーン1つまで、無くてよい。美文を足さない。
4. AI調を出さない。感情ラベル（悲しかった、怒った）で段落を終えない。定型の連発をしない。章末を要約で締めない。
5. 口調を混ぜない。話者タグを外しても誰か分かること。
6. 頼まれていないファイル、続編、新キャラ、設定拡張を作らない。既出の固有名詞と事実は上書きしない。矛盾があれば指摘して止める。
7. 冒頭を天気、目覚め、通学路の日常で始めない。

## 受け入れ基準

- ログライン1行で、誰が何を失い何をする話か言える。
- 視点、一人称、結末が `plot.md` の先頭にある。
- 章内で視点が揺れていない。
- 口調サンプルと矛盾するセリフがない。
- 章末に未解決が1つある。
- 指定外の文章、ファイル、設定を足していない。
